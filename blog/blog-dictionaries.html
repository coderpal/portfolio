Comprehensive Guide to Python Dictionaries

A deep dive into Python dictionaries — from basic creation to hash table internals, dict views, merge operators, custom keys, performance characteristics, and production patterns used in real backend systems.

If Python had a single data structure to rule them all, it would be the dictionary. Dictionaries are not just one of Python's built-in types — they are the backbone of the language itself. Module namespaces are dictionaries. Class attributes are dictionaries. Function keyword arguments are dictionaries. JSON deserializes into dictionaries. Configuration files become dictionaries. Database rows become dictionaries.

You cannot write serious Python code without mastering dictionaries. They are the workhorse of data transformation, the default choice for structured data, and the foundation of countless patterns you use every day — from caching to configuration to grouping to counting.

Under the hood, a Python dictionary is a highly optimized hash table. Since Python 3.7, dictionaries also preserve insertion order — a change that transformed them from unordered mappings into predictable, iterable sequences of key-value pairs. Combined with O(1) lookups, this makes dictionaries one of the most versatile and powerful data structures in any programming language.

🟢 Chapter 1: The Foundation

What is a Dictionary?

A dictionary in Python is an ordered (since 3.7), mutable collection of key-value pairs, where each key is unique and hashable. Let's unpack each of those words:

  • Ordered: Since Python 3.7, dictionaries preserve the order in which keys were inserted. Iterating over a dict yields keys in insertion order.
  • Mutable: You can add, modify, and remove key-value pairs after creation.
  • Key-value pairs: Each entry maps a key to a value. Keys must be unique; values can be anything.
  • Hashable keys: Keys must be immutable types (strings, numbers, tuples of immutables) with a stable hash value.
The big change in Python 3.7: Before 3.7, dictionaries were unordered — iteration order was arbitrary. Since 3.7, insertion order is guaranteed as part of the language spec. This transformed dicts into predictable, iterable structures and made many patterns (like JSON serialization) deterministic.

Creating Dictionaries

Python offers several ways to create dictionaries, each with its own use case:

# Curly braces — most common
user = {"name": "Rahul", "age": 30, "role": "Backend Developer"}
empty = {}

# dict() constructor with keyword arguments
user = dict(name="Rahul", age=30, role="Backend Developer")
# ⚠️ Keys must be valid identifiers (strings)

# dict() from a list of tuples
pairs = [("name", "Rahul"), ("age", 30), ("role", "Backend Developer")]
user = dict(pairs)

# dict.fromkeys() — create a dict with the same value for all keys
keys = ["name", "age", "role"]
template = dict.fromkeys(keys, None)
# {'name': None, 'age': None, 'role': None}

# ⚠️ Gotcha: fromkeys with a mutable default
bad = dict.fromkeys(["a", "b", "c"], [])
bad["a"].append(1)
print(bad)  # {'a': [1], 'b': [1], 'c': [1]} — all share the SAME list!

# ✅ Fix: use a comprehension for independent mutable defaults
good = {k: [] for k in ["a", "b", "c"]}
good["a"].append(1)
print(good)  # {'a': [1], 'b': [], 'c': []} — independent lists

# Dict comprehension
squares = {x: x**2 for x in range(5)}
# {0: 0, 1: 1, 2: 4, 3: 9, 4: 16}

# From zip() — combine two sequences into a dict
names = ["Rahul", "Amit", "Priya"]
ages = [30, 25, 28]
people = dict(zip(names, ages))
# {'Rahul': 30, 'Amit': 25, 'Priya': 28}

# ⚠️ You cannot use unhashable types as keys
# bad = {[1, 2]: "value"}   # ❌ TypeError: unhashable type: 'list'
# bad = {{"a": 1}: "value"} # ❌ TypeError: unhashable type: 'dict'
# bad = {{1, 2}: "value"}   # ❌ TypeError: unhashable type: 'set'

# ✅ But tuples, strings, numbers, and frozensets work fine
good = {
    (0, 0): "origin",
    "name": "Rahul",
    42: "the answer",
    frozenset({1, 2}): "a set as key"
}

Accessing Values

There are three main ways to access values in a dictionary, each with different behavior for missing keys:

user = {"name": "Rahul", "age": 30, "role": "Backend Developer"}

# 1. Square brackets — raises KeyError if missing
print(user["name"])         # "Rahul"
# print(user["email"])      # ❌ KeyError: 'email'

# 2. get() — returns None (or a default) if missing
print(user.get("name"))     # "Rahul"
print(user.get("email"))    # None
print(user.get("email", "not provided"))  # "not provided"

# 3. setdefault() — returns value if exists, otherwise sets and returns default
print(user.setdefault("name", "Unknown"))     # "Rahul" (already exists)
print(user.setdefault("email", "not provided"))  # "not provided" (sets it!)
print(user)  # {'name': 'Rahul', 'age': 30, 'role': 'Backend Developer', 'email': 'not provided'}
Rule of thumb: Use get() when a missing key is expected and you have a sensible default. Use [] when the key must exist (you want to know immediately if it doesn't). Use setdefault() when you want to lazily initialize a value on first access.

Adding, Updating, and Removing

user = {"name": "Rahul", "age": 30}

# Add or update a single key
user["email"] = "rahul@example.com"  # Add new key
user["age"] = 31                      # Update existing key

# update() — merge another dict or iterable of pairs
user.update({"role": "Developer", "age": 32})  # Merges, overwrites existing
user.update([("city", "Mumbai"), ("country", "India")])  # From list of tuples
user.update(country="India")  # Keyword arguments

# Python 3.9+ merge operators
other = {"email": "rahul@example.com", "age": 33}

# | creates a NEW dict (doesn't modify originals)
merged = user | other
print(merged)  # {'name': 'Rahul', 'age': 33, 'email': 'rahul@example.com', ...}

# |= modifies in place
user |= other  # user is now updated with 'other's values

# Removing keys
del user["email"]           # Removes the key (KeyError if missing)
# del user["nonexistent"]   # ❌ KeyError

removed = user.pop("age")   # Removes and returns the value
# removed = user.pop("age", None)  # Returns default if missing

key, value = user.popitem()  # Removes and returns the LAST inserted pair (LIFO)
# Returns ('country', 'India') in Python 3.7+

user.clear()  # Removes all items

Iteration Patterns

Dictionaries support multiple iteration patterns, each yielding different things:

user = {"name": "Rahul", "age": 30, "role": "Developer"}

# Iterate over keys (default)
for key in user:
    print(key)
# name, age, role

# Explicitly iterate over keys
for key in user.keys():
    print(key)

# Iterate over values
for value in user.values():
    print(value)
# Rahul, 30, Developer

# Iterate over key-value pairs
for key, value in user.items():
    print(f"{key}: {value}")
# name: Rahul
# age: 30
# role: Developer

# Dictionary comprehension during iteration
upper_keys = {k.upper(): v for k, v in user.items()}
# {'NAME': 'Rahul', 'AGE': 30, 'ROLE': 'Developer'}

Essential Dictionary Methods

user = {"name": "Rahul", "age": 30, "role": "Developer"}

# len() — number of key-value pairs
print(len(user))  # 3

# Membership testing (checks KEYS, not values)
print("name" in user)       # True
print("Rahul" in user)      # False (Rahul is a value, not a key)
print("email" not in user)  # True

# keys(), values(), items() — return dict views (see Chapter 2)
print(user.keys())    # dict_keys(['name', 'age', 'role'])
print(user.values())  # dict_values(['Rahul', 30, 'Developer'])
print(user.items())   # dict_items([('name', 'Rahul'), ('age', 30), ...])

# copy() — shallow copy
original = {"name": "Rahul", "skills": ["Python", "SQL"]}
shallow = original.copy()
shallow["name"] = "Amit"       # Doesn't affect original
shallow["skills"].append("Go") # DOES affect original (shared reference!)
print(original["skills"])  # ['Python', 'SQL', 'Go']

# Deep copy for nested structures
import copy
original = {"name": "Rahul", "skills": ["Python", "SQL"]}
deep = copy.deepcopy(original)
deep["skills"].append("Go")
print(original["skills"])  # ['Python', 'SQL'] — unaffected

🟡 Chapter 2: Intermediate — Comprehensions, Views, and Patterns

Dict Comprehensions

Dict comprehensions are one of Python's most elegant features. They let you create dictionaries from iterables in a single, readable line. 

# Basic: square each number
squares = {x: x**2 for x in range(5)}
# {0: 0, 1: 1, 2: 4, 3: 9, 4: 16}

# With condition: only even numbers
even_squares = {x: x**2 for x in range(10) if x % 2 == 0}
# {0: 0, 2: 4, 4: 16, 6: 36, 8: 64}

# Transform keys
names = ["alice", "bob", "charlie"]
lower_to_upper = {name: name.upper() for name in names}
# {'alice': 'ALICE', 'bob': 'BOB', 'charlie': 'CHARLIE'}

# Swap keys and values
original = {"a": 1, "b": 2, "c": 3}
swapped = {v: k for k, v in original.items()}
# {1: 'a', 2: 'b', 3: 'c'}

# Filter a dictionary
users = {
    "alice": {"active": True, "score": 85},
    "bob": {"active": False, "score": 72},
    "charlie": {"active": True, "score": 91}
}
active_users = {k: v for k, v in users.items() if v["active"]}
# {'alice': {...}, 'charlie': {...}}

# Nested dict comprehension
matrix = {(i, j): i * j for i in range(3) for j in range(3)}
# {(0, 0): 0, (0, 1): 0, ..., (2, 2): 4}

# Invert a dict with list values
from collections import defaultdict
original = {"a": [1, 2], "b": [2, 3], "c": [1, 3]}
inverted = defaultdict(list)
for k, values in original.items():
    for v in values:
        inverted[v].append(k)
# {1: ['a', 'c'], 2: ['a', 'b'], 3: ['b', 'c']}
Rule of thumb: If your comprehension needs nested loops that are hard to read, convert it to a regular for loop. Readability beats cleverness.

Merging Dictionaries

Python has evolved several ways to merge dictionaries. Here's the complete picture:

defaults = {"timeout": 30, "retries": 3, "verbose": False}
user_config = {"timeout": 60, "verbose": True}

# Method 1: update() — modifies in place, pre-Python 3.5
merged = defaults.copy()
merged.update(user_config)
# {'timeout': 60, 'retries': 3, 'verbose': True}

# Method 2: ** unpacking — creates new dict, Python 3.5+
merged = {**defaults, **user_config}
# {'timeout': 60, 'retries': 3, 'verbose': True}

# Method 3: | operator — creates new dict, Python 3.9+ (RECOMMENDED)
merged = defaults | user_config
# {'timeout': 60, 'retries': 3, 'verbose': True}

# Method 4: |= operator — modifies in place, Python 3.9+
defaults |= user_config
# defaults is now {'timeout': 60, 'retries': 3, 'verbose': True}

# Order matters: later dicts override earlier ones
a = {"x": 1, "y": 2}
b = {"y": 3, "z": 4}
print(a | b)  # {'x': 1, 'y': 3, 'z': 4} — b's 'y' wins
print(b | a)  # {'y': 2, 'z': 4, 'x': 1} — a's 'y' wins

# Chain multiple dicts
final = defaults | user_config | overrides | environment
Recommendation: Use the | operator for Python 3.9+. It's the most readable and most Pythonic. Fall back to {**a, **b} for older versions.

Dict Views: Set-Like Objects

The objects returned by keys(), values(), and items() are not lists — they are dynamic views that reflect changes to the dictionary. More importantly, keys() and items() views behave like sets, supporting set operations. 

user = {"name": "Rahul", "age": 30, "role": "Developer"}

# Views are dynamic — they reflect dict changes
keys_view = user.keys()
print(keys_view)  # dict_keys(['name', 'age', 'role'])

user["email"] = "rahul@example.com"
print(keys_view)  # dict_keys(['name', 'age', 'role', 'email']) — updated!

# keys() views support set operations
d1 = {"a": 1, "b": 2, "c": 3}
d2 = {"b": 20, "c": 30, "d": 40}

print(d1.keys() & d2.keys())   # {'b', 'c'} — intersection
print(d1.keys() | d2.keys())   # {'a', 'b', 'c', 'd'} — union
print(d1.keys() - d2.keys())   # {'a'} — difference
print(d1.keys() ^ d2.keys())   # {'a', 'd'} — symmetric difference

# items() views also support set operations
print(d1.items() & d2.items())  # {('b', 20), ('c', 30)} — common pairs
print(d1.items() - d2.items())  # {('a', 1)} — in d1 but not d2

# values() views do NOT support set operations (values may have duplicates)
# print(d1.values() & d2.values())  # ❌ TypeError

# Practical use: finding common keys
def merge_configs(defaults, overrides):
    common_keys = defaults.keys() & overrides.keys()
    print(f"Overriding keys: {common_keys}")
    return defaults | overrides

# Practical use: finding missing keys
required = {"name", "email", "password"}
provided = user.keys()
missing = required - provided
print(f"Missing fields: {missing}")

Nested Dictionaries

Dictionaries can contain other dictionaries, forming hierarchical structures. This is common for representing JSON data, configuration, and complex records. 

# Nested dict
company = {
    "name": "Tech Corp",
    "address": {
        "street": "123 Main St",
        "city": "Mumbai",
        "country": "India"
    },
    "employees": [
        {"name": "Rahul", "role": "Developer"},
        {"name": "Amit", "role": "Designer"}
    ]
}

# Accessing nested values
city = company["address"]["city"]  # "Mumbai"
first_employee = company["employees"][0]["name"]  # "Rahul"

# ⚠️ KeyError if any intermediate key is missing
# zip_code = company["address"]["zip"]  # ❌ KeyError

# ✅ Safe access with chained get()
zip_code = company.get("address", {}).get("zip", "N/A")

# Updating nested values
company["address"]["zip"] = "400001"

# ⚠️ Creating nested dicts the hard way
data = {}
# data["users"]["alice"]["score"] = 100  # ❌ KeyError: 'users'

# ✅ Using setdefault()
data.setdefault("users", {}).setdefault("alice", {})["score"] = 100

# ✅ Better: using defaultdict (see Chapter 4)

Counting and Grouping Patterns

These are among the most common dictionary patterns in Python. Master them, and you'll solve a huge class of problems elegantly. 

# ❌ Counting the hard way
words = ["apple", "banana", "apple", "cherry", "banana", "apple"]
counts = {}
for word in words:
    if word not in counts:
        counts[word] = 0
    counts[word] += 1

# ✅ Better: using dict.get()
counts = {}
for word in words:
    counts[word] = counts.get(word, 0) + 1

# ✅ Even better: using collections.Counter (see Chapter 4)
from collections import Counter
counts = Counter(words)

# ❌ Grouping the hard way
users = [
    {"name": "Alice", "dept": "Engineering"},
    {"name": "Bob", "dept": "Sales"},
    {"name": "Charlie", "dept": "Engineering"},
]
by_dept = {}
for user in users:
    dept = user["dept"]
    if dept not in by_dept:
        by_dept[dept] = []
    by_dept[dept].append(user)

# ✅ Better: using setdefault()
by_dept = {}
for user in users:
    by_dept.setdefault(user["dept"], []).append(user)

# ✅ Even better: using collections.defaultdict (see Chapter 4)

🔴 Chapter 3: Advanced — Hash Tables, Internals, and Performance

How Dictionaries Work Internally

Under the hood, a Python dictionary is a hash table. When you insert a key-value pair, Python:

  1. Computes the hash of the key (via hash(key)).
  2. Uses the hash to compute an index into an internal array.
  3. Stores the key-value pair at that index.
  4. On lookup, recomputes the hash and jumps directly to the index — O(1).

When two keys hash to the same index (a collision), Python uses open addressing with probing to find the next available slot. 

# Every hashable object has a hash value
print(hash("hello"))   # Some integer
print(hash(42))        # 42 (integers hash to themselves)
print(hash((1, 2, 3))) # Some integer

# Hash is consistent within a Python session
print(hash("hello") == hash("hello"))  # True

# But NOT consistent across Python invocations (security feature)
# Run this twice: python -c 'print(hash("hello"))'
# You'll get different values each time! (PYTHONHASHSEED randomization)

# Unhashable types cannot be dict keys
# d = {[1, 2]: "value"}  # ❌ TypeError: unhashable type: 'list'

# Custom class as dict key
class User:
    def __init__(self, email):
        self.email = email
    
    def __hash__(self):
        return hash(self.email)
    
    def __eq__(self, other):
        if not isinstance(other, User):
            return False
        return self.email == other.email

u1 = User("rahul@example.com")
u2 = User("rahul@example.com")

users = {u1: "active"}
print(users[u2])  # "active" — u2 equals u1, so it finds the same entry
Important: If you override __eq__(), you must also override __hash__(). Otherwise, Python sets __hash__ to None, making instances unhashable.

The Compact Dict (Python 3.6+)

Before Python 3.6, dictionaries used a sparse hash table that wasted a lot of memory. Raymond Hettinger redesigned the implementation to use a compact representation:

  • A sparse array of indices (the hash table).
  • A dense array of entries (actual key-value pairs in insertion order).

This redesign reduced memory usage by 20-25% and incidentally preserved insertion order — which became a language guarantee in Python 3.7. 

import sys

# Compare memory usage
lst = list(range(1000))
dct = {i: i for i in range(1000)}

print(sys.getsizeof(lst))  # ~9000 bytes
print(sys.getsizeof(dct))  # ~37000 bytes

# Dicts use ~4x more memory than lists
# Trade-off: memory for O(1) key-based lookup

# For small dicts, the overhead is significant
empty_dict = {}
empty_list = []
print(sys.getsizeof(empty_dict))  # 232 bytes (significant overhead!)
print(sys.getsizeof(empty_list))  # 56 bytes

Performance Characteristics

Understanding time complexity is critical for writing efficient code:

Operation Average Case Worst Case Notes
d[key] — Lookup O(1) O(N) O(N) only with many hash collisions
d[key] = value — Insert O(1) O(N) May trigger resize
del d[key] — Delete O(1) O(N) Raises KeyError if missing
key in d — Membership O(1) O(N) Checks keys only
value in d.values() O(N) O(N) Must scan all values
len(d) O(1) O(1) Stored in object header
d.copy() O(N) O(N) Shallow copy
d1 | d2 — Merge O(M) O(N+M) M is size of d2
Iteration O(N) O(N) Visits each entry once

OrderedDict vs. Regular Dict

Since Python 3.7, regular dicts preserve insertion order. So why does collections.OrderedDict still exist? 

from collections import OrderedDict

# Regular dict — preserves insertion order since Python 3.7
regular = {"a": 1, "b": 2, "c": 3}
print(list(regular.keys()))  # ['a', 'b', 'c']

# OrderedDict — same behavior, but with extra features
ordered = OrderedDict({"a": 1, "b": 2, "c": 3})

# Feature 1: move_to_end()
ordered.move_to_end("a")
print(list(ordered.keys()))  # ['b', 'c', 'a']

ordered.move_to_end("b", last=False)
print(list(ordered.keys()))  # ['b', 'a', 'c']

# Feature 2: popitem() with last= argument
key, value = ordered.popitem(last=True)   # Removes last (LIFO)
key, value = ordered.popitem(last=False)  # Removes first (FIFO)

# Feature 3: Equality is order-sensitive
d1 = {"a": 1, "b": 2}
d2 = {"b": 2, "a": 1}
print(d1 == d2)  # True — regular dict equality ignores order

od1 = OrderedDict({"a": 1, "b": 2})
od2 = OrderedDict({"b": 2, "a": 1})
print(od1 == od2)  # False — OrderedDict equality considers order
When to use OrderedDict: Use it when you need move_to_end(), order-sensitive equality, or explicit FIFO/LIFO operations via popitem(). For simple ordered mappings, regular dicts are faster and use less memory.

MappingProxyType: Read-Only Dict Views

Python provides types.MappingProxyType to create read-only views of dictionaries. This is useful when you want to expose a dict without allowing modification. 

from types import MappingProxyType

config = {
    "debug": False,
    "timeout": 30,
    "retries": 3
}

# Create a read-only view
readonly_config = MappingProxyType(config)

print(readonly_config["debug"])  # False — reading works
print(len(readonly_config))      # 3 — len() works
print("timeout" in readonly_config)  # True — membership works

# But modification is blocked
# readonly_config["debug"] = True  # ❌ TypeError: 'mappingproxy' object does not support item assignment
# readonly_config["new"] = 1       # ❌ TypeError
# del readonly_config["debug"]     # ❌ TypeError

# The view is dynamic — changes to the original are reflected
config["debug"] = True
print(readonly_config["debug"])  # True — view reflects the change

# Real-world use: exposing class __dict__ as read-only
class Config:
    SETTINGS = {"debug": False, "timeout": 30}
    
    @classmethod
    def get_settings(cls):
        return MappingProxyType(cls.SETTINGS)

settings = Config.get_settings()
# settings["debug"] = True  # ❌ TypeError — protected!

🏭 Chapter 4: Production Patterns

Pattern 1: Caching and Memoization

Dictionaries are the foundation of caching. Use them to avoid recomputing expensive operations. 

# Manual caching with a dict
_cache = {}

def expensive_computation(x, y):
    key = (x, y)
    if key not in _cache:
        result = x ** y + x * y  # Expensive operation
        _cache[key] = result
    return _cache[key]

# Better: use functools.lru_cache (uses a dict internally)
from functools import lru_cache

@lru_cache(maxsize=128)
def fibonacci(n):
    if n < 2:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)

print(fibonacci(100))  # Instant, even for large n

# For unbounded cache, use cache (Python 3.9+)
from functools import cache

@cache
def factorial(n):
    return 1 if n == 0 else n * factorial(n - 1)

# Custom cache with TTL (time-to-live)
import time

class TTLCache:
    def __init__(self, ttl_seconds=60):
        self._cache = {}
        self._ttl = ttl_seconds
    
    def get(self, key):
        if key in self._cache:
            value, timestamp = self._cache[key]
            if time.time() - timestamp < self._ttl:
                return value
            del self._cache[key]  # Expired
        return None
    
    def set(self, key, value):
        self._cache[key] = (value, time.time())

Pattern 2: Configuration Management

Dictionaries are the natural choice for configuration, especially when merging defaults with user overrides. 

# Default configuration
DEFAULT_CONFIG = {
    "database": {
        "host": "localhost",
        "port": 5432,
        "name": "mydb",
        "timeout": 30
    },
    "logging": {
        "level": "INFO",
        "format": "%(asctime)s - %(message)s"
    },
    "features": {
        "enable_cache": True,
        "max_connections": 100
    }
}

def load_config(user_config_path):
    import json
    with open(user_config_path) as f:
        user_config = json.load(f)
    
    # Deep merge: recursively merge nested dicts
    def deep_merge(defaults, overrides):
        result = defaults.copy()
        for key, value in overrides.items():
            if key in result and isinstance(result[key], dict) and isinstance(value, dict):
                result[key] = deep_merge(result[key], value)
            else:
                result[key] = value
        return result
    
    return deep_merge(DEFAULT_CONFIG, user_config)

# Usage
config = load_config("config.json")
print(config["database"]["host"])  # User's value or "localhost"

Pattern 3: JSON Handling

JSON maps naturally to Python dictionaries. Master this conversion for API work. 

import json

# Dict to JSON string
user = {"name": "Rahul", "age": 30, "active": True}
json_str = json.dumps(user)
# '{"name": "Rahul", "age": 30, "active": true}'

# Pretty-printed JSON
pretty = json.dumps(user, indent=2, sort_keys=True)

# JSON string to dict
parsed = json.loads(json_str)
# {'name': 'Rahul', 'age': 30, 'active': True}

# Read JSON from file
with open("data.json") as f:
    data = json.load(f)  # Returns a dict

# Write dict to JSON file
with open("output.json", "w") as f:
    json.dump(user, f, indent=2)

# Handling API responses
import requests

response = requests.get("https://api.example.com/users/1")
user_data = response.json()  # Returns a dict

# Safe access with defaults
name = user_data.get("name", "Unknown")
email = user_data.get("contact", {}).get("email", "N/A")

# ⚠️ Handling non-string keys (JSON only supports string keys)
# When you dump a dict with non-string keys, they become strings
data = {1: "one", 2: "two"}
json_str = json.dumps(data)  # '{"1": "one", "2": "two"}'
parsed = json.loads(json_str)  # {'1': 'one', '2': 'two'} — keys are now strings!

Pattern 4: Grouping Data with defaultdict

collections.defaultdict automatically creates missing keys with a default value factory. This eliminates the need for setdefault() or if key not in checks. 

from collections import defaultdict

# Grouping by a key
users = [
    {"name": "Alice", "dept": "Engineering"},
    {"name": "Bob", "dept": "Sales"},
    {"name": "Charlie", "dept": "Engineering"},
    {"name": "Diana", "dept": "Marketing"},
]

by_dept = defaultdict(list)
for user in users:
    by_dept[user["dept"]].append(user["name"])

print(dict(by_dept))
# {'Engineering': ['Alice', 'Charlie'], 'Sales': ['Bob'], 'Marketing': ['Diana']}

# Counting occurrences
words = ["apple", "banana", "apple", "cherry", "banana", "apple"]
counts = defaultdict(int)
for word in words:
    counts[word] += 1

print(dict(counts))  # {'apple': 3, 'banana': 2, 'cherry': 1}

# Even better: use Counter
from collections import Counter
counts = Counter(words)
print(counts.most_common(2))  # [('apple', 3), ('banana', 2)]

# Nested defaultdict for 2D grouping
data = [
    ("Engineering", "Alice", 85),
    ("Engineering", "Bob", 92),
    ("Sales", "Charlie", 78),
]

scores = defaultdict(lambda: defaultdict(list))
for dept, name, score in data:
    scores[dept][name].append(score)

# Building a graph (adjacency list)
graph = defaultdict(set)
edges = [("A", "B"), ("B", "C"), ("A", "C"), ("C", "A")]
for src, dst in edges:
    graph[src].add(dst)

print(dict(graph))
# {'A': {'B', 'C'}, 'B': {'C'}, 'C': {'A'}}

Pattern 5: Avoiding Common Pitfalls

# ❌ PITFALL 1: Modifying a dict while iterating
user = {"name": "Rahul", "age": 30, "role": "Developer"}
# for key in user:
#     if key == "age":
#         del user[key]  # ❌ RuntimeError: dictionary changed size during iteration

# ✅ Fix: iterate over a copy of keys
for key in list(user.keys()):
    if key == "age":
        del user[key]

# Or use dict comprehension
user = {k: v for k, v in user.items() if k != "age"}

# ❌ PITFALL 2: Using mutable default values with fromkeys()
bad = dict.fromkeys(["a", "b", "c"], [])
bad["a"].append(1)
print(bad)  # {'a': [1], 'b': [1], 'c': [1]} — all share the same list!

# ✅ Fix: use a comprehension
good = {k: [] for k in ["a", "b", "c"]}

# ❌ PITFALL 3: KeyError on missing keys
# value = user["nonexistent"]  # ❌ KeyError

# ✅ Fix: use get() with a default
value = user.get("nonexistent", "default_value")

# ❌ PITFALL 4: Shallow copy surprises
original = {"name": "Rahul", "skills": ["Python", "SQL"]}
copy = original.copy()
copy["skills"].append("Go")
print(original["skills"])  # ['Python', 'SQL', 'Go'] — modified!

# ✅ Fix: use deepcopy for nested structures
import copy
deep = copy.deepcopy(original)
deep["skills"].append("Go")
print(original["skills"])  # ['Python', 'SQL'] — unaffected

# ❌ PITFALL 5: Assuming dict order is guaranteed before Python 3.7
# In Python 3.6 and earlier, iteration order was arbitrary
# Since 3.7, insertion order is guaranteed

# ❌ PITFALL 6: Using unhashable types as keys
# d = {[1, 2]: "value"}  # ❌ TypeError
# ✅ Fix: use tuples or frozensets
d = {(1, 2): "value"}

# ❌ PITFALL 7: Forgetting that dict views are dynamic
user = {"name": "Rahul"}
keys = user.keys()
user["age"] = 30
print(keys)  # dict_keys(['name', 'age']) — view reflects the change!
# If you need a static snapshot, convert to list: list(user.keys())

# ❌ PITFALL 8: Checking for value membership (slow!)
user = {"name": "Rahul", "age": 30, "role": "Developer"}
# if "Rahul" in user:  # ❌ Checks KEYS, not values — returns False
# ✅ Fix: check values explicitly
if "Rahul" in user.values():  # O(N) — slow for large dicts
    print("Found!")
# For frequent value lookups, maintain a reverse index

🎯 Conclusion

Dictionaries are the heart of Python. They power everything from function arguments to JSON handling to caching to configuration. A deep understanding of dictionaries — not just the basics, but the internals, the performance characteristics, and the idiomatic patterns — is what separates competent Python code from truly excellent Python code.

The key takeaways:

  • Dictionaries are hash tables — key lookup is O(1) on average, making them ideal for mappings and caches.
  • Dictionaries preserve insertion order — since Python 3.7, iteration order is guaranteed.
  • Keys must be hashable — strings, numbers, and tuples of immutables work; lists and dicts don't.
  • Use get() for safe access — it returns a default instead of raising KeyError.
  • Dict views are set-like — keys() and items() support set operations.
  • Use defaultdict for grouping and counting — it eliminates boilerplate for missing keys.
  • Use | and |= for merging — Python 3.9+ operators are the most Pythonic.
  • Use deepcopy for nested dicts — shallow copies share mutable nested objects.

Master these concepts, and you will write Python code that is not just correct, but elegant. You will choose the right patterns for the right problems, avoid common pitfalls, and build systems that are fast, readable, and maintainable.
